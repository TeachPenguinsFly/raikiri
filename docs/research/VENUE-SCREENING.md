Дата замеров: 2026-09-20. Профиль: гражданин Беларуси с польским ВНЖ.
Цель: маркет-дата + фандинг гейтвеи. Деплой не требуется, только локальный тест.

**До починки bitget, mexc и bitfinex ПАДАЛИ** — stack-use-after-scope.
`fill_cursor` был объявлен внутри блока `if (can_trade)`, а поток поллера
захватывает его по ссылке и переживает блок. Ровно тот случай, о котором
предупреждал комментарий строкой выше (по нему уже вынесены `funding_cursor`
и `ledger_replay_due`). Починено, коммит `ce716d5`, 1731 тест зелёный.

### Lighter — важное
`/api/v1/funding-rates` отдаёт `{"market_id":132,"exchange":"binance","symbol":"ARC","rate":0.0001}`.
Ставка **импортируется с binance**, а значит по построению не расходится с ней.
Фандинг-арбитраж Lighter↔Binance мёртв на уровне дизайна.

## 4. Aster — первый новый адаптер (в работе)

Побайтово совместим с binance fapi: те же пути, те же имена полей, тот же
заголовок `x-mbx-used-weight-1m`, тот же лимит 2400/мин.

**Но цены НЕ те же.** Замер 2026-09-20 по дельтам заголовка веса:

```
/fapi/v1/time                    1
/fapi/v1/exchangeInfo            1
/fapi/v1/premiumIndex   (table) 10   <- binance берёт 1
/fapi/v1/fundingInfo            10   <- binance берёт 1
/fapi/v1/depth       (limit 100) 5
/fapi/v1/depth      (limit 1000) 20
/fapi/v1/ticker/24hr    (table) 40
/fapi/v1/ticker/24hr  (1 symbol) 1
```

Перенести бинансовый прайс-лист вместе с парсерами — значит пустить
десятикратный объём по двум путям, по которым поллер фандинга ходит каждый цикл.

Прочее: 602 символа (597 PERPETUAL, 5 в PENDING_TRADING с пустым contractType);
квоты USDT 589 / USD1 11 / "U" 2; **testnet отсутствует** (DNS не резолвится);
приватная сторона подписывается **EVM-кошельком**, а не HMAC — поэтому ордерный
путь не просто не построен, он требует другого подписанта.

Сделано: форк из binance, вычищен ордерный путь, `VenueId::Aster`, строка caps,
CMake, веса. Осталось: отказывающий ExecutionClient, регистрация в gatewayd,
фикстуры и тесты, smoke.

## 6. Цена одного адаптера

Полный binance — 5636 строк. Без ордеров/приватного стрима/подписи остаётся ~3500.
`ExecutionClient` всё равно обязателен (`execution->start()` зовётся безусловно),
но 9 методов отказа — это ~60 строк. 24 новых биржи = ~84 000 строк; поэтому
скрининг, а не стройка, решает задачу.

## 7. Добор по эндпоинтам (2026-09-20, вторая волна)

- **Bitrue** — `fapi` требует авторизацию даже на `exchangeInfo`: `{"code":"-1002",
  "msg":"You are not authorized to execute this request"}`. Публичной маркет-даты
  по сути нет; гейтвей без ключей не поднимется.
- **CoinW** — 388 контрактов, но инструменты зовутся `BTC` с числовым `id`, в ряду
  нет ни одного поля с фандингом, публичный путь к ставке не находится
  (`/v1/perpumPublic/*` отвечает 404 на всех вариантах), а тикер по `BTC-USDT`
  возвращает пустой массив. Нестандартный API, дорогой в поддержке.
- **Deepcoin** — форма API как у okx (`instType`/`instId`), но угаданные пути
  фандинга дают 404; `mark-price` просит `instType`. Нужны официальные доки.
- **LBank** — перпы есть на `lbkperp.lbank.com` через
  `/cfd/openApi/v1/pub/marketData?productGroup=SwapU`. Среди символов
  индексные контракты (`HK50USDT`), то есть не только крипта.
- **Клонов binance fapi, кроме Aster, нет.** Проверены bitunix, coinex, bitrue,
  bigone, digifinex, deepcoin, coinw, hotcoin — ни один не отвечает
  бинансовой формой на `/fapi/v1/exchangeInfo`. Значит дешёвая дорога, которая
  сработала с Aster, больше нигде не повторится: каждая следующая биржа —
  полный адаптер.
- **Backpack** — 190 рынков, из них **103 PERP** и 87 SPOT. Схема своя
  (`baseSymbol`, `filters.price.tickSize`).
